# 券商文件支持范围——1.1.0-alpha.2-r1

> **券商数据留在你的电脑上。** 当前本地版 TAD 在你的电脑上导入、处理和保存券商文件与账户数据，不会上传到 TAD 云端。界面中的“上传”是把文件交给本机运行的程序；用户自行通过公开反馈、邮件或外部服务分享资料，是另外的动作。


[English](broker-support.en.md) · [导出指南](broker-export.zh.md) · [真实数据上手](personal-data.zh.md) · [安装与合成测试](README.zh.md)

**支持的是下列具体报表格式，不是该券商的所有导出文件。** 套件内应用为
**1.1.0-alpha.2-r1**，已包含三家原生及 Standard CSV 独立 Connector。首轮个人数据试用范围为
**USD 投资账户、股票与已支持格式的标准美股期权记录**；不凭券商名称承诺支持
其他币种、地区、语言、产品或调整／非标准期权。不提供自动登录券商或自动同步。

## 应准备哪些文件？

| 券商 | 交易记录输入 | 当前持仓输入 | 补充依据及限制 |
| --- | --- | --- | --- |
| Moomoo | 英文表头的订单／成交历史 CSV，保留成交明细和可提供的费用列 | 包含 `Symbol`、`Quantity`、`Current price`、`Average Cost`、`Market Value`、`Unrealized P/L`、`Currency` 的 CSV | 必须确认真实仓位日期；这类持仓文件不能单独证明现金余额，订单历史也不等于完整非交易现金流水。 |
| Chase／J.P. Morgan 投资账户 | 完整 **31 列**投资交易 CSV，包含账户身份、日期、类型、证券描述、数量及 USD 金额 | 完整 **71 列**投资持仓 CSV，包含 `As of`、`Ticker`、`Quantity`、`Asset Class`、`Pricing Date` | 已实现损益 CSV 已有历史核对 Reader，但**不是**普通上传更新流程的第三类财务输入。支票、信用卡、商户流水不属于此格式。 |
| E*TRADE | 带 `Account Activity for ...` 的 CSV，使用明确日期区间或支持的 Current Year／Prior Year 标题，保留完整 13 列交易表 | 完整 `View Summary - All Positions` CSV，带账户汇总、`Net Account Value`、持仓表及 `Generated at ... ET` | CASH 行是余额观察值；Cash Purchasing Power 不是现金；TOTAL 已含现金。筛选后的持仓表、缺账户或生成日期的表不属于可替代格式。 |
| Standard CSV（转换／用户提供） | TAD.transactions.v1.csv | TAD.positions.v1.csv，CASH单列 | USD股票／标准100乘数美股期权；声明来源、精确账户身份，未知值和部分覆盖保持明确。[指南](standard-import.zh.md)。 |

三家均保留券商原件，使用同一套核心重建和分析。文件识别成功后仍可能需要核对
才能应用。把 XLSX／PDF 改成 CSV 后缀、翻译表头，或把其他券商伪装成 Moomoo
文件，都不等于格式受支持。**未支持券商可按[标准CSV Connector及模板](standard-import.zh.md)转换，不要伪装成原生券商格式。**

## 已实现、已验证和待验证分别是什么？

| 层次 | 依据与边界 |
| --- | --- |
| 已实现 | 三家独立、版本化 Connector，共用核心；已有账户核对、预览、明确应用及增量更新流程。 |
| 下载包已在开发机核对 | 三家合成案例均覆盖新账户、流水和持仓、增量、重叠去重、重复应用，以及文档／草稿／显示设置保留；Moomoo 另含期权和共享支撑检查。 |
| 项目既有私有历史 | Reader 使用过既有真实账户导入／对账经验；不代表新测试者文件已通过认证，也不公开私人依据。 |
| 待验证 | 测试用户 Mac 兼容性及各自真实导出、账户和历史；Chase／E*TRADE 公开合成案例是简单股票／现金，不是完整期权生命周期认证。 |

Mac 签名及芯片／系统边界继续见[安装说明](README.zh.md)。此次仅更新文档，
不重建程序，也不扩大已验证范围。

## 什么情况会待核？

| 待核项 | 对结果的影响 | 下一步 |
| --- | --- | --- |
| 缺早期买入、期初数量／成本，或账户身份未确定 | 已平仓收益、剩余成本、策略支撑可能不完整；最新持仓不能补出缺失历史 | 使用同账户已有早期原件或有依据的期初边界；不编造交易、不默认填零；无法确认则保存草稿。 |
| 缺现金活动或独立余额依据 | 交易／持仓可能已有可用结果，现金仍部分待核；购买力、净资产和现金含义不同 | 核对期初现金、转账、分红、利息、费用与余额日期；仅归档 PDF 不会使现金通过核验。 |
| E*TRADE Current Year／Prior Year | 绝对年份取自实际交易行，不取今天；不能证明全年完整，空文件／混年文件会待核 | 优先重新导出明确日期范围；无法确认覆盖和期初则保存草稿并反馈脱敏问题，不改标题强行通过。 |
| 格式变更、未知活动、调整期权，或转仓／到期／行权关联不明 | 可能无法读取，或相关交易链／持仓／分析不完整 | 本地保留原件，反馈版本、报表类型和脱敏错误；如有则重新导出支持报表，不把特殊事件改成普通交易。 |
| 增量更新后保留的历史期初依据 | 已知核心限制：即使期初依据仍在，也可能无法使完整入账现金通过资格检查 | 保留现有依据并反馈；这可能是系统工作，不是用户缺文件，不反复上传或修改余额来消除状态。 |

**已应用不等于已完全对账。** 当前估值使用保存的券商观察值，不是实时行情。
已知收益可以保留显示，而部分成本、回报或现金仍不可用；匹配子集回报不是整个
账户回报。见[状态与下一步](personal-data.zh.md#理解状态)。

## Statement 与历史参考文件

PDF statement 可归档、关联账户，供后续查阅。**不支持通用 PDF 自动提取、
statement 自动转换交易，或仅凭已归档 PDF 自动核验现金。**

Chase 已实现损益参考 Reader 保留既有历史核对能力，但普通公开文件上传流程
仅应用流水和持仓。不要把损益参考文件改成流水。本文不承诺已有自助历史参考
采用按钮；已有依据若无法被正常流程消费，应本地保留并反馈缺口，不在公开反馈
中附原件。
