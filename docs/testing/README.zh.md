**两条独立路径：**本页和未改动的下载套件用于合成验收；通过后可按[真实数据上手](personal-data.zh.md)自愿在本机试用个人文件，先看[支持矩阵](broker-support.zh.md)和[导出指南](broker-export.zh.md)。合成与个人账户分开环境。下文“仅合成／不使用真实文件”针对合成验收任务，不表示程序拒绝支持的真实文件。


分发版本：**1.1.0-alpha.1 公开技术预览**。包内应用版本为 **1.1.0-tester-review.1**，保持已验收原包不变。测试用户 Mac 的独立安装验收仍**尚未完成**。

## 1. 下载、核对并打开程序

在 Release 页选择 **TAD-1.1.0-alpha.1-macOS-arm64-test-kit.zip**。GitHub 自动生成的 Source code ZIP/TAR 是 showcase 文档，不是应用。测试下载已包含合成资料和验收表；解压后继续下列步骤。

解压外层套件，打开 START-HERE.html 看中英文总说明。
application/ 中是已验收的应用 ZIP，SHA256 应为：

`2621bafd4ba65d2900d381f2484d7e5118fd9728ab0ec3b01f4e714bd9592ee7`

可选操作员校验：终端输入 `cd `，把解压后的套件目录拖入并回车，然后执行
`shasum -a 256 -c SHA256SUMS`，各项应显示 OK。任何校验不符均停止。
SHA 只核对文件身份，不等于 Apple 公证。

再解压内层应用 ZIP。普通新用户双击 Setup.command 即可，缺省创建
~/Applications/TAD-Test；已有目录不会被覆盖，重复初始化也不会自动升级。

首次公开测试使用默认的全新 ~/Applications/TAD-Test 即可。
若该目录已有数据或不完整，请保留。需要新目录时，把 Setup.command 拖入终端，
追加 ` --destination "$HOME/Applications/TAD-Preview-New"` 并回车。
8888 被占用时可加 ` --port 8889`（需为空闲端口），不需要编辑 JSON。
请单独记录命令行辅助操作；它不能替代 Finder 双击通过的结论。

进入新建个人目录，双击 Start.command，等待就绪和浏览器自动打开。
未自动打开时先记为失败，再用终端显示的地址辅助排查；默认是
http://127.0.0.1:8888 。应看到空白上传页，账户数为 0。
不要把个人环境建在下载的程序目录内，也不要移动已初始化的个人目录，配置有路径绑定。

## 2. 先完整走一遍 Moomoo 新用户流程

以下全部为 2026 年历史测试日期，不是今天。

- 在上传文件中选择 cases/moomoo/01-initial/ 的流水及仓位两份 CSV，点击上传并读取。
  保留流水原名 History-Margin Account(0001).csv，其中包含合成账户身份。
- 每份文件进入“查看／核对”，确认 Moomoo、流水或仓位类型。
  仓位的“文件实际仓位日期”为 2026-01-06。修改日期需要重新读取时，先保存、
  检查刷新后的预览，再确认账户归属。
- 账户关联选择“新账户（先确认身份）”：名称 Synthetic Moomoo、末四位 0001、
  类型 Margin／保证金账户；两份文件填写同一组值。勾选归属确认并保存核对，归档可选。
- 只勾选这两份文件“纳入本次更新”，点击“检查选定文件”。在进入的向导中核对：
  完整账户身份 0001、期初日期 2026-01-01、期初现金 USD 10,000、
  **期初证券持仓为空**、结束日期 2026-01-06。由于本套件提供了完整合成历史，
  可以确认期初持仓及交易范围完整；不要把最新仓位倒填为期初仓位。
- 查看总结后明确“确认并应用”。文件显示已归档或待更新不等于账户已应用。

首次应有 SYN 股票 +10、SYN280121C50000 +1、SYN270115C100000 -1、
SYN270219C100000 -1。已实现收益为 0，保存的浮盈合计 USD 370，现金算术值 8,400。
估值日期是 2026-01-06，不是实时行情。Moomoo 仓位 CSV 不含现金余额行，
所以这里现金来自期初及交易算术，不是另一份券商现金证明。

## 3. Moomoo 更新、重复与重启

上传 cases/moomoo/02-update/ 的两份文件，关联已有 Synthetic Moomoo，
仓位日期 2026-01-07，检查并确认归属。累计流水应为 4 条已有记录、1 条新增记录：
以 USD 12 卖出 4 股 SYN。预览本身不应用，明确“确认并应用”才更新。

进入投资分析，选择此账户、全部策略、已实现期间 2026，并核对当前保存日期。
更新后的预期结果：

- SYN 股票 +6，剩余股票成本 USD 60；三条期权数量仍为 +1、-1、-1。
  此次卖出成本 40、收入 48、已实现毛收益 USD 8。
- 股票浮盈 12，long call 浮盈 200，两条 short call 浮盈分别 100 和 50，
  保存的浮盈合计 USD 362。已实现加这些保存浮盈为 370。
- 现金算术：10,000 - 100 - 2,000 + 300 + 200 + 48 = USD 8,448。
  加证券净市值 1,922，保存的净资产为 10,370。
- 一张 long call 不能重复成为两张 long，对两条 short 各自提供完整支撑；
  10／6 股股票也不能被算成 100 股。部分支撑或待核范围应保留，不能强行配对。
- 核对回报率／资金效率旁的期间和适用范围，不把匹配子集回报当作全账户回报，
  不在多个策略合计中重复加入同一份支撑成本。

再次上传同一累计流水应不增加新交易，不要新建重复账户；如再次应用，数量和收益
应保持不变。归档示例 PDF，留一份待应用更新草稿，修改账户显示设置。
停止再启动，并在系统重启后重新启动，检查原件、文档名、草稿和显示设置均保留。
只对自己的已完成预检环境重复 Setup，核对程序版本、配置、端口及数据不被改写。
不要用个人目录做覆盖试验；如遇端口／不完整目录拒绝，应记录而非清理或杀进程。

## 5. 归档、证据与限制

cases/archive-only/SYNTHETIC-statement.pdf 是有效的合成 PDF，仅用于归档。
改成有意义的名字，重新打开／下载，重启后再查。它不应产生交易或改变现金，
也不是期初现金的证明，不能拿它消除现金待核。

现金算术与对账资格分开。本套件只手工确认期初值，没有独立证明完整入账现金或
可用现金范围；现金可显示部分待核、已核验期末余额不可用，不要求把 8,448／992
显示成已验证现金。保留历史期初证明在增量更新后另有既有已知限制。
请分别如实记录原因和影响，不填零、不以“算术一致”替代“对账通过”。
合成数据与保存报价也不证明真实券商历史完整。

在 ACCEPTANCE.zh.md 标注通过、受阻、已知限制、未执行，并保存脱敏截图。
本地技术证据与公开反馈分开，不发送真实券商原件、账户号、含个人路径的日志、
